# 课程术语：基础库 → 候选库 → 确认库

自动术语默认关闭，通过手动入口 `automatic_terms=true` 启用。基础库仍使用人工维护的 `course_glossary.py`；候选和证据只存在原有加密数据库的 `meta` 表，不进入公开提示词文件。

## 三层规则

**基础库**：课程预设的专业词，优先进入识别提示。没有候选也能正常运行。

**候选库**：摘要模型在同一次请求中返回最多 15 个专业术语候选。Python 验证词条、所声明来源和连续引用确实存在于输入，同时要求词条出现在非补充、非疑点摘要段落中。排除作业、考试等课程事项及指令、网址、数字等。每个候选保留课次、来源、原文引用及引用哈希，每种来源最多 4 条，共最多 12 条。没有额外关键词 API 请求，但结构化证据会增加 token。

**确认库**：读取时重新核对引用完整性及佐证，不直接信任已存的 stage。满足下列任一规则才可成为后续课堂提示：

- 可见 PPT/OCR 文字与实际豆包复核文本同时支持该词。
- 至少两堂不同课次、两段不同引用提供外部于 Qwen 的支持（PPT/OCR 或豆包）。同一课次重跑和不同课堂重复使用完全相同引用不能凑足门槛。

只在 Qwen/ASR 多次出现不能晋升。待核、疑点、不清晰、不确定、误写、否定名称等引用不计为佐证。某词已进入该堂冻结提示时，这堂产生的材料不作为该词的新增晋升佐证，避免提示诱导后再把输出当证明。旧版仅有 source 标签、没有完整引用和提示历史的记录降为候选，不沿用旧的“重复 ASR 两次即可启用”规则。

规则是自动确认的证据门槛，不等同于人工审定或准确率保证。OCR 和云端仍可能重复出错；此版本暂未增加人工确认、拒绝、锁定及撤销界面。后续人工治理需要持久化状态，以免被下一次自动提取覆盖。

## 同堂冻结，下堂更新

准备阶段调用 `AutomaticGlossary.freeze(course_title, sub_id)`，只使用本课**更早日期**的确认记录。排除同堂、同一天、未来课堂、外课程及被删除课次的记录；日期不明时仅用基础库。读取最近 100 条有效记录，最终基础词与确认词去重后最多 30 个，基础词优先。

冻结结果保存基础词、确认词、最终词表、课次日期和词表 SHA-256，并进入音频计划。全部 Qwen Worker、豆包热词和疑难筛选使用这份词表。恢复仍使用原词表，中途数据库增加候选、删词或其他课完成都不会改变本堂输入。新候选在摘要后入库，最早供下一日期的课堂使用，不在同堂再跑 ASR。

候选记录仍使用 `auto_glossary:<course_id>:<sub_id>` 键，与现有数据库并行合并、课次范围发布及历史摘要兼容。`AutomaticGlossary.stages()` 可读取候选/确认状态及证据；`freeze()` 返回实际使用的词表。保存的 stage 是审计快照，之后读取会按完整有效课次重新推导。

词库仅作为 Qwen 上下文和豆包识别提示，不是强制替换规则。保留原始识别、疑难标记和来源引用。隔离测试可以证明筛选、冻结及持久化逻辑，但真实提升仍需获批后做课堂对照。
