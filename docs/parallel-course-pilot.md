# 课程级并行试运行

入口：`parallel_pilot.yml`，仅手动执行；未替换 main 的定时任务。
课程列表沿用私密的 `COURSE_IDS`，矩阵输出只显示序号，不显示课程标识。
`max-parallel: 5`，`fail-fast: false`：最多同时五门，每门内部课次顺序处理。

各课程 job 使用本分支的 Qwen3-ASR-1.7B 全量识别与有界豆包复核；
SenseVoice 已从本分支运行链移除，尚未替换 main 的线上引擎。`automatic_terms` 可选择启用分支中的
自动词库，默认关闭。

worker 不发送邮件，也不推送 data 分支；关闭重复课程目录爬取。
worker 只导出该课程的数据和自动词库元数据，不携带其他课程的旧快照。
结果使用独立用途派生密钥和 AES-GCM 加密，绑定本次 run_id 与课程序号；
只上传密文，保留一天。

一个发布 job 重新读取最新数据库，校验并合并可用成果，再按课程发邮件，
最后沿用现有加密分片发布逻辑。某个课程失败时仍收集已保存的有效成果；
若全部未产生可用成果，发布失败，不用空数据库替换已有数据。
部分课程失败仍会让整个 workflow 显示失败，不会隐藏失败状态。

整个 workflow 与现有数据工作流使用同一并发组，避免跨工作流同时发邮件/发布。
组内课程 job 仍可五路并行。此入口尚未进行真实多课程邮件端到端试运行。

邮件沿用成功发送后记录 emailed_at 的语义，不承诺 SMTP 恰好一次：
若 SMTP 已成功但数据库尚未发布就中断，下次仍存在重复发送风险。
