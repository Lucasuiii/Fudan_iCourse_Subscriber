# 单堂课 ASR 共享队列

手动运行 `parallel_pilot.yml`，选择 `shard_mode=shared` 才启用。现有定时入口和手动默认仍是两路固定分片；自动术语默认关闭。部署启用需要另行安排，隔离课堂验证仍在进行。

## 调度范围和数量

共享范围为**一堂课的原始 VAD 块**。Runner 每次领取一个块，保存结果后再领取下一个，优先领取音频较长的块。空闲 Runner 可以领取本堂课剩余的任何块，不受原静态分组限制；每堂课完成后独立进入复核、摘要和发布。

| 累计待识别音频（包括原块重叠部分） | Runner 数量 |
| --- | --- |
| 无待识别块 | 0 |
| ≤30 分钟 | 1 |
| >30 且 ≤60 分钟 | 2 |
| >60 分钟 | 3 |

块数比 Runner 数少时进一步缩减数量。门槛是初始策略，尚无共享队列真实课堂耗时证据。恢复沿用原计划的 Worker 数，不因已完成块减少而重新生成音频计划。重试时没有剩余任务的 Worker 跳过模型加载。

仍最多同时运行 5 条课堂流水线，每条流水线任一阶段最多占 3 台，总上限 15。其他课程空出的名额暂不借给本堂课，Runner 也不跨课程抢块；这是保守的全局额度预留，不是跨所有课程的统一池。采用同一流程的运行仍由现有 concurrency 锁串行协调。

## 原始输入和汇总

- 使用现有 Silero VAD 和约两分钟切片，保留原始时间戳及播放回退链。正式 pilot 解码使用 `aresample=async=1:first_pts=0`，在转成无时间戳的 PCM 前按音轨时间戳补齐间隙，防止间隙被压掉后字幕、作业截图定位前移；不会按照视频声明时长人为追加尾部静音。传统单 Runner 入口的解码命令保持原样。
- 保留整段音频 SHA-256、逐块 FLAC SHA-256、模型版本、课次和冻结词表；仅复用已读的音频字节计算哈希，未取消完整性检查。
- 每台 Worker 连续领块期间保留 Qwen 模型，退出时释放。豆包只在统一汇总阶段参与疑难复核，沿用整堂课共享的现有额度，分片不能各自获得一份额度。
- 全部原计划块完成后才允许汇总。静态 shard 分组继续作为结果校验和装配接口，不能限制动态领取，也不能被当成实际 Worker 的耗时统计。
- 原始排序、边界去重、LectureRunner 保存及恢复、独立发布接口保持不变。私密原始 Qwen 导出可直接读取完整共享队列结果，仍不调用模型。

## 持久化和故障恢复

每个 run/task 使用独立 orphan Git 分支 `codex/asr-queue-<run_id>-<task_slot>`。分支树只有 `queue.enc`，包含经过 AES-GCM 加密并绑定 repo/run/task 的状态及识别文本；不存音频、明文课堂内容或密钥。不会修改 main/data。ASR job 因此需要 `contents: write`，用途限定在该临时协调分支。

领取与完成采用乐观并发：候选提交只以读取时的版本为父提交，普通 Git push 遇到竞争更新会被拒绝，重新读取后重试；禁止 force push。网络错误与确定不存在分开处理，不能因读取失败而重建空队列。

已领取块没有按墙钟过期的租约，较慢的推理不会被另一台机子抢走。新 Actions attempt 才能接管旧 attempt 的未完成领取；这个边界依赖 GitHub 重试前旧 attempt 已结束。失败只补未持久化完成的块。

识别完成先写本地加密 `shared-local.enc`，再保存远端队列。远端保存失败时保留领取状态，防止同一 attempt 的其他 Worker 再识别这个已落盘的块。Actions 的 always 上传步骤保存本地检查点。下一 attempt 的**每台** Worker 都先恢复所有旧 Worker 的本地结果，才允许领取任务；避免恢复速度不同造成抢先重复解码。成功分片的旧检查点也纳入恢复。

硬终止发生在解码完成但任何持久化之前的那一个块仍可能需要重做，无法承诺进程内结果必然可恢复。检查点缺失、过期、输入不符、当前领取仍活跃或结果冲突时停止，不能默认为全新输入。跨 run 恢复还要求旧 run 已结束，复用原音频、全部已完成文本和现有复核额度检查点，不重置云端额度。

`qwen-production-shared-*` artifacts 保留 7 天。协调分支目前保留供恢复/原始文本导出，尚未自动清理；每次状态更新会增加加密 Git 历史。上生产前还需实测 Git 往返与历史存储开销，并设计不影响恢复窗口的清理策略。

准备阶段在时长校验之前保存原始样本对应的 FLAC、哈希、实际/媒体时长、差值、解码退出状态及冻结词表；解码或校验失败也保留已获取音频供诊断。校验失败不创建 ASR 队列，重试不会重新获取已有失败音频，也不会认可不完整输入。公开验证审计仅输出数字、哈希和状态；音频、课次详情和词表仍在加密 artifact 中。只读 `inspect_audio` 可导出尚未生成分块计划的失败音频用于诊断。

修复后需要重新获取原先未保留音频的失败课堂时，显式使用 `validation_source_run_id`。它只允许已结束且准备失败、没有音频/ASR 计划或复核状态的正式隔离试跑；沿用原队列中的唯一课次、空数据库、原历史及冻结词表，重新绑定到新 run。课程、倒序位置、截止日期或术语模式不匹配时拒绝，不重新选择最新课。发布和邮件必须关闭；已有音频或识别结果应走恢复路径，不能通过此入口重置识别或云端额度。每次新获取仍需用户授权。

## 验证边界

隔离测试覆盖快慢 Worker 动态领块、真实本地 Git 并发写入冲突、加密绑定、失败恢复不重复解码、未完成禁止摘要、原时间线和冻结词表。测试中的 Qwen 推理结果使用替身，不代表真实课堂识别质量或提速幅度。工作流的准备、模型安装、排队、协调保存、ASR、复核和发布开销需要分别统计。
