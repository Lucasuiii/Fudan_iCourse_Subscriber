# 单堂课跨 Runner ASR 隔离试验

手动入口：`.github/workflows/qwen_sharded_pilot.yml`。第一版用于与已完成的
生产 Qwen 单路课堂试跑作实际业务对照。此对照入口继续独立保留：不发送邮件、不写正式数据库，不修改 `COURSE_IDS`。
当前 main 的日常订阅通过另一个 [正式分片入口](parallel-course-pilot.md) 接入 `LectureRunner` 保存与发布链。
本文介绍的是独立对照工具，课程准备、ASR、复核和摘要仅由手动 dispatch 启动。
推送代码的合成分块测试不启动课程识别。

## 并发与分块

- 课程上限 5，整个批次的活动 Runner 上限 15。
- 准备（最多 5）和批次清单校验（1）完成后，每门课通过
  `.github/workflows/qwen_sharded_course.yml` 独立执行 ASR → 汇总。
  一门课自己的分片结束就开始汇总，不等其他课程；失败分片会使该课汇总
  在云端调用前拒绝不完整结果，其他课仍可完成。
- 调用层最多 5 门课，单课 ASR 最多 3 台，汇总占 1 台且等待本课 ASR
  全部结束；识别和汇总交错时总 Runner 仍不超过 5 × 3 = 15。
  reusable workflow 调用本身不占等待 Runner。批次和单课分片矩阵均
  `fail-fast: false`，成功课程不会因其他课程失败而被取消。
- 批次校验仍检查所有加密清单、重复课次和总分片数；输入准备仍有整批
  等待，当前改动只移除了 ASR 与汇总之间的跨课程等待。
  该结构采用 [GitHub 的矩阵调用 reusable workflow](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows#using-a-matrix-strategy-with-a-reusable-workflow)。
- 试验与现有订阅工作流共用 `icourse-data-${repository}` 批次并发组，
  避免多次工作流叠加。手动试验会与定时任务相互排队，定时规则不变。
  旧提交上已经启动的工作流不会因此被中断或重新调度。
  GitHub 的并发组不是 FIFO 队列，多个待运行请求可能互相替换；不要连续
  提交多批试验，需核对 Actions 的实际状态。
- `shard_mode=2` 默认两路；`auto` 是尚待验证的策略：累计模型输入时长
  ≤60 分钟两路，>60 分钟三路。块不足时自动减少 Runner 数。
- 权重是原块样本数，包含短暂停顿和原边界 padding。长块优先分给当前
  累计时长最少的 Runner；不重新切块、不拼接成新时间轴。

准备阶段从完整基线产物读取具体课次、原分块、VAD 窗口和术语，使用既有
播放地址回退链重新获取该课次；不再选择“最新课次”。新音频时长必须与基线
相符，各块通过无损 FLAC 分发，保留原始样本数和原录播时间戳。
接近三小时获取上限（相差不超过 0.1 秒）的输入默认视为疑似截断并停止。
不能因 WAV／编码舍入到上限前 1 毫秒而被误判为完整课堂。

ASR Worker 调用生产 `QwenTranscriber.recognize_blocks`，复用同一模型版本、
提示词复述重试及低信息过滤；每个 Worker 只拿本分片音频，不拿 UIS、豆包
或摘要服务凭据。Worker 保留原始文本，汇总恢复原块编号顺序后统一执行
现有边界去重，原始块仍保留供对齐和复核。

## 第一次两路对照

先等正在运行的单路基线产生完整识别产物，再执行以下命令：

```sh
gh workflow run qwen_sharded_pilot.yml \
  --repo Lucasuiii/Fudan_iCourse_Subscriber \
  --ref codex/qwen-production-pilot \
  -f baselines='[{"run_id":"37209166684","artifact":"qwen-asr-encrypted-result-1"},{"run_id":"37209538072","artifact":"qwen-asr-encrypted-result-0"}]' \
  -f shard_mode=2 \
  -f review_profile=production
```

若基线仍在运行，而需要立即开始两路识别，可额外设置
`-f prepare_mode=private_latest`。此模式仅用于已有的私密测试课程槽位
（artifact 后缀 0／1），使用同一私密课程选择、最新可播放课次回退链和
生产 Silero VAD／约两分钟分块规则，自行准备分片；不读取未完成的基线，
也不把规划清单标记为已完成 ASR。现有原始录播时间轴保持不变。

汇总时才下载原单路结果，核对课次、时长、模型和术语。若原基线尚未
上传，汇总在云端调用前停止，完整分片仍保留；待基线上传后重试失败的
汇总 job 即可。诊断与正式最终检查点使用不同 artifact，预检失败不会
制造一个阻止重试的“空检查点”。验证后的基线副本也保存在加密最终结果，
方便基线原 artifact 过期后复用 ASR。

重新解析最新课次可能与旧基线不同，发现不一致时禁止自动复核和摘要。
两次 VAD 边界逐项检查；边界不一致时不计算按块文本差异，报告明确
标记这种限制，避免将不同块误当成相同输入。

用户明确接受非完整对照时可设 `allow_partial_comparison=true`，允许独立
分块模式继续识别接近获取上限的输入，汇总也允许同一课次的时长差异或
未完成基线。仍核对课次、模型、术语，仍要求本次全部计划块成功。
结果分别标注 ASR 计划是否完成、课堂范围是否完整、对照限制；不把
未经核验的课堂标为完整，摘要提示也明确只总结已识别输入。

如果旧提交的所有 ASR Worker 已成功，但严格汇总尚未生成正式最终产物，
可用 `reuse_sharded_run_id=旧run` 配合这个显式选项做一次仅汇总的补充运行。
入口先通过 API 确认旧课程不存在最终化检查点，再校验所有成功 ASR 分片。
只重新绑定加密清单和传递已完成块，不重新获取音频、加载模型或识别。
旧最终化检查点已存在时拒绝该途径，防止丢失额度状态后重复云端复核。
若只需补充旧批次的一门课，可在该 `baselines` 条目中设置
`reuse_source_slot` 为原课程槽位（0–4）；新批次仍顺序编号。原课次和基线
引用必须匹配，避免为了保留槽位而重复复核已经完成的其他课程。
部分对照只描述各自输入范围内的耗时、资源和文字差异；不得将时长不同
的整段耗时比宣称为两路识别的纯提速收益。

`baselines` 最多五个条目，默认必须来自完整的 `authorized_full_runtime` 产物，
且具有正确模型版本、课次及原块清单；不接受公开短音频。
仅显式部分对照允许有原块清单的未完成基线。
重复课次被拒绝。旧基线 artifact 保留一天，需在过期前完成准备下载；
准备成功后，基线副本随新加密输入包保留七天。

旧基线没有保存音频哈希，这次按用户确认采用同一课次和块时间轴的业务
对照，不声称是严格同输入 A/B。新输入记录音频 SHA-256、各块校验值及
不可变清单指纹，为本次重试和后续复现提供依据。

首轮保持 `review_profile=production`（当时为 600 秒／12 段；当前默认 900 秒／40 段），避免把额度变化
混入并行质量与总耗时比较。`pilot15` 历史试验档仍为 900 秒／18 段，
与当前生产默认的 900 秒／40 段分开统计。该选项需要一次新的隔离试验，不会改变
正在运行的旧基线，也不能在同一 run 重试时变更额度。
第一次分片试验完整成功后，可保留同一 `baselines` 数组、顺序和 `shard_mode`，设置
`reuse_sharded_run_id=该分片试验的 run_id, review_profile=pilot15`。
入口核验原清单、音频包、全部成功分片及完整复核／摘要后复用 ASR，
不重新拉取录播或加载 ASR 模型，只执行新的额度对照。
此时耗时只代表重新复核和摘要，不能作为一次新的 ASR 提速测量。

## 汇总、复核与重试

- 验证清单指纹、块编号、时间戳、模型及分配，所有预期块都必须成功。
  缺失、重复、截断、错误配置或全空正文均禁止复核和摘要。
- Worker 每识别完一个块，原子保存加密检查点；GitHub “Re-run failed jobs”
  复用成功 Worker，并让失败 Worker 只识别自身尚未完成的块。
- 恢复产物时，只有 API 确认产物不存在才允许从头开始；网络错误或产物
  过期不会被当成“首次运行”。恢复失败也不会覆盖原产物。
- 汇总阶段才调用一次整堂课复核及摘要，所有分片共用当前默认的 900 秒／40 段；首轮历史试验为 600 秒／12 段，`pilot15` 历史试验为 900 秒／18 段。
  依赖范围只包含本课分片；准备、复用和最终化仍沿用同一 caller run_id
  与课程槽位，原 artifact 名称、加密上下文和额度检查点保持兼容。
  单个复核片段仍最多 60 秒，疑点原文和定位规则不放宽，官方字幕只作旁证。
- 复核开始前先保存额度状态，每次中间保存都镜像到待上传产物。
  复核中断且额度无法确认时，自动重试停止，保留原始 ASR 和诊断，
  不通过重置计数再次消费整堂额度。复核已完成时只补失败的摘要阶段。
- 一门课缺片不会阻止其他完整课程导出摘要；失败仍让该工作流显示失败。

这是现有隔离 benchmark 的复核与摘要流程，不是生产 `LectureRunner`
邮件、数据库或自动词库的端到端测试。自动关键词默认关闭。

## 产物与评估

公开日志和矩阵只显示课程／分片序号与资源指标；音频、基线、正文、PPT
辅助材料、结果和错误正文使用独立测试密钥 AES-GCM 加密。新分片包绑定
run_id、课程序号和用途。音频先无损压缩再加密，产物保留七天，Runner
临时明文在任务末清理。产物仍占 GitHub artifact 存储配额；实际容量和
传输开销需纳入对照，不承诺模型启动与分发开销可以忽略。

每课最终 `qwen-shard-final-{slot}` 产物中的 `result.enc` 沿用基线 QASR1
解密格式，包含：

- 原始块、去重后的正文及时间段、VAD、空块列表、模型与术语快照；
- 分片负载、每块解码耗时、各 Worker 累计耗时、重试／复用块数；
- 基线 ASR 耗时、逐块文本差异、正文是否相同、基线摘要是否完整；
- 复核候选数、是否达到候选上限、定位失败原因、已用和剩余额度；
- 到摘要阶段的工作流墙钟与累计 Runner 秒数，以及基线对应课程 job 耗时。

工作流时间快照包含准备和分发等 job 开销，墙钟包含排队，累计 Runner
时间不包含排队；当前最终上传、清理和更早失败工作流的成本不在快照内。
完整 run 结束后还应读取 Actions 最终 job 时间作最终对照，跨多课程的
累计计算量是批次指标，不能直接当成某一门课的计算量。

文本相同率不是准确率。重要疑点是否漏选、云端是否改善术语和公式，需要
抽样听审；未用满额度但仍有错误时，先检查筛选／定位，不据此自动提高
生产限额。两路收益和 60 分钟阈值均待课堂实测后确定。
